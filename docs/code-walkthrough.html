dataset.py

From raw CSVs to model inputs

TRAIN_END, VAL_END

The Rossmann split dates.

TRAIN_END = "2014-12-31"
VAL_END = "2015-04-30"
  • Train is every target day up to 31 Dec 2014, validation up to 30 Apr 2015, test is May to July 2015.
  • Splitting by date, not at random, is required for time series: the model is never trained on days after the ones it is tested on.

load(name)

The single entry point the other files call.

def load(name):
    """Return sales, open flags, features and (train_end, val_end) for a dataset."""
    if name == "rossmann":
        return (*load_rossmann(), (TRAIN_END, VAL_END))
    if name == "paper":
        return (*load_paper(), ("2015-12-31", "2016-12-31"))   # the paper's split
    raise ValueError(name)
  • Returns four things: sales, open flags, features, and the two split dates.
  • *load_rossmann() unpacks the three tables, then the split dates are added as a fourth item.
  • Because of this function, train.py and evaluate.py never need to know which dataset they are working on.

load_rossmann(path)

Turns 1,017,209 rows of store-days into a day × store matrix plus 22 daily features.

def load_rossmann(path="data/train.csv"):
    """Return daily sales and open flags (dates x stores) plus daily exogenous features."""
    df = pd.read_csv(path, parse_dates=["Date"], dtype={"StateHoliday": str})

    # keep only stores that have a record on every day
    days_per_store = df.groupby("Store").size()
    complete = days_per_store[days_per_store == df["Date"].nunique()].index
    df = df[df["Store"].isin(complete)]

    sales = df.pivot(index="Date", columns="Store", values="Sales").sort_index()
    is_open = df.pivot(index="Date", columns="Store", values="Open").sort_index()

    shares = df.groupby("Date").agg(
        state_holiday=("StateHoliday", lambda s: (s != "0").mean()),
        school_holiday=("SchoolHoliday", "mean"),
        promo=("Promo", "mean"),
    )
    features = calendar_features(sales.index).join(shares)
    return sales, is_open, features
  • dtype={"StateHoliday": str}: the column mixes the number 0 with the letters a, b, c. Reading it as text stops pandas treating 0 and "0" as different values.
  • groupby("Store").size() counts days per store. Only stores with all 942 days are kept: 934 of 1,115 (ADR 0001).
  • pivot(index="Date", columns="Store") makes one row per day and one column per store (942 × 934). This is the paper's step of grouping all series per day.
  • shares: for each day, the fraction of stores on a state holiday, a school holiday and a promo. Three numbers per day instead of 934 × 3 columns.
  • The final features are 7 day-of-week + 12 month + 3 shares = 22 columns.
If asked

Why drop 181 stores instead of filling their missing months? Filling six months of sales would invent data; a complete matrix keeps every value real.

load_paper(path)

The same shape for the paper's dataset, used for the bonus comparison.

def load_paper(path="data/train_paper.csv"):
    """Store Item Demand data used by the paper: 10 stores x 50 items = 500 series."""
    df = pd.read_csv(path, parse_dates=["date"])
    sales = df.pivot_table(index="date", columns=["store", "item"], values="sales").sort_index()
    is_open = pd.DataFrame(1, index=sales.index, columns=sales.columns)   # never closed

    holidays = USFederalHolidayCalendar().holidays(sales.index.min(), sales.index.max())
    features = calendar_features(sales.index)
    features["us_holiday"] = sales.index.isin(holidays).astype(float)
    return sales, is_open, features
  • pivot_table(columns=["store", "item"]) gives 500 columns, one per store-item pair, over 1,826 days.
  • is_open is all ones because this dataset has no closed days.
  • USFederalHolidayCalendar adds a 0/1 holiday flag, matching the paper's "US holiday calendar". Features: 7 + 12 + 1 = 20.

calendar_features(dates)

One-hot day of week and month, as in the paper's Table 1.

def calendar_features(dates):
    """One-hot day of week (7) and month (12)."""
    dow = pd.get_dummies(dates.day_of_week, prefix="dow")
    month = pd.get_dummies(dates.month, prefix="month")
    return pd.concat([dow, month], axis=1).set_index(dates).astype(float)
  • get_dummies turns a value like Tuesday into seven columns where only dow_1 is 1.
  • set_index(dates) lines the rows up with the sales matrix; astype(float) turns True/False into 1.0/0.0.

make_windows(...)

The core of the data pipeline: scale, add features, slide a 7-day window, split by date.

def make_windows(sales, features, lags=7, log_sales=False, next_day_features=False,
                 train_end=TRAIN_END, val_end=VAL_END):
    """Build (X, y) windows for train / val / test, split by the date of the target day.

    X[i] holds `lags` past days of [scaled sales of every store, features].
    y[i] is the scaled sales of every store on the target day.
    """
    values = np.log1p(sales.values) if log_sales else sales.values.astype(float)

    # fit the scaler on training days only, to avoid leaking the future
    train_rows = sales.index <= train_end
    scaler = MinMaxScaler().fit(values[train_rows])
    scaled = scaler.transform(values)

    feats = features.values
    if next_day_features:
        # each step carries the calendar of the following day,
        # so the last step tells the model about the target day
        feats = np.roll(feats, -1, axis=0)
    inputs = np.hstack([scaled, feats])

    X, y = [], []
    for t in range(lags, len(sales)):
        X.append(inputs[t - lags:t])
        y.append(scaled[t])
    X, y = np.array(X, dtype="float32"), np.array(y, dtype="float32")
    target_dates = sales.index[lags:]

    splits = {
        "train": target_dates <= train_end,
        "val": (target_dates > train_end) & (target_dates <= val_end),
        "test": target_dates > val_end,
    }
    data = {name: (X[mask], y[mask], target_dates[mask]) for name, mask in splits.items()}
    return data, scaler
  • Log (optional): np.log1p is bonus candidate (c). It was rejected on validation.
  • Scaling: MinMaxScaler().fit(values[train_rows]) learns each store's min and max from training days only. If it had seen 2015, the future would leak into training. Features are already 0 to 1, so only sales are scaled.
  • Next-day features (optional): np.roll(feats, -1) moves every feature row up by one day, so the last step of each window describes the day being predicted. This is bonus candidate (a), the one we kept. The row that wraps around to the end is never used as input.
  • Join: np.hstack puts 934 scaled sales next to 22 features: 956 columns per day.
  • Window loop: for each day t, the input is days t-7 … t-1 and the target is day t for all stores. This is the paper's "shift the series to create labels".
  • Split: by the target day's date. A test window for 1 May uses real sales from 24 to 30 April as input, which is allowed because those days are already known (ADR 0002).
If asked

What shape is one sample? X is (7, 956) and y is (934,). Rossmann gives 723 train, 120 validation and 92 test samples.

to_sales(scaled, scaler, log_sales)

Turns model outputs back into real sales.

def to_sales(scaled, scaler, log_sales=False):
    """Undo scaling (and log) to get predictions back in real sales units."""
    values = scaler.inverse_transform(scaled)
    return np.expm1(values) if log_sales else values
  • inverse_transform undoes the 0 to 1 scaling store by store; expm1 undoes the log if it was used.
  • Every metric is computed on real sales, so MAE and RMSE are in euros of daily sales.

models.py

The three networks in Keras

Hyperparameters

Every setting from the paper's Table 2 in one place.

LSTM_UNITS = 100
FILTERS = (128, 256, 500)
POOL_SIZES = (2, 7, 10)
KERNEL_SIZE = 3          # not given in the paper (our choice)
DENSE_UNITS = 100        # parallel LSTM branch, not given in the paper (our choice)
INNER_DROPOUT = 0.2
FINAL_DROPOUT = 0.3
LEARNING_RATE = 0.001
  • KERNEL_SIZE and DENSE_UNITS are our choices because the paper does not state them.
  • A live change in the discussion (LSTM units, learning rate) is a one-line edit here.

init()

The paper's Gaussian weight initialisation: mean 0, standard deviation 0.05.

def init():
    """Gaussian weight initialisation, mean 0 and std 0.05 (paper)."""
    return keras.initializers.RandomNormal(mean=0.0, stddev=0.05)
  • It is a function so that every layer gets its own fresh initializer object.
  • It is applied to each layer's input weights; the LSTM's recurrent weights keep the Keras default.

conv_block(x)

Three rounds of Conv1D then average pooling, then Flatten. Shared by both hybrids.

def conv_block(x):
    """Three Conv1D + AveragePooling stages, then Flatten."""
    for filters, pool in zip(FILTERS, POOL_SIZES):
        x = layers.Conv1D(filters, KERNEL_SIZE, padding="same", activation="relu",
                          kernel_initializer=init())(x)
        x = layers.AveragePooling1D(pool, padding="same")(x)
    return layers.Flatten()(x)
  • Filters grow 128 → 256 → 500 and pool sizes are 2, 7, 10, as in the paper.
  • padding="same" is required: pools of 7 and 10 are bigger than what is left of the 7-day axis, and without it Keras raises a shape error.
  • The time axis shrinks 7 → 4 → 1 → 1, so the last convolution sees one step that summarises the whole week.
If asked

Why average pooling, not max pooling? The paper says the three Conv1D layers are each followed by an average pooling layer.

stacked_cnn_lstm(n_lags, n_features, n_outputs)

S-CNN-LSTM: LSTM first, CNN on top of it, one path.

def stacked_cnn_lstm(n_lags, n_features, n_outputs):
    """S-CNN-LSTM: LSTM -> Dropout -> CNN block -> Dropout -> Dense."""
    inputs = keras.Input(shape=(n_lags, n_features))
    x = layers.LSTM(LSTM_UNITS, activation="relu", return_sequences=True,
                    kernel_initializer=init())(inputs)
    x = layers.Dropout(INNER_DROPOUT)(x)
    x = conv_block(x)
    x = layers.Dropout(FINAL_DROPOUT)(x)
    outputs = layers.Dense(n_outputs, kernel_initializer=init())(x)
    return compile_model(keras.Model(inputs, outputs, name="S-CNN-LSTM"))
  • return_sequences=True is the key detail: the LSTM outputs its state for all 7 days, shape (7, 100), so the CNN still has a sequence to slide over.
  • The paper puts the LSTM first so the CNN works on a sequence that is still in time order.
  • Dropout 0.2 after the LSTM and 0.3 before the output layer. 1.41M parameters.

parallel_cnn_lstm(n_lags, n_features, n_outputs)

P-CNN-LSTM: an LSTM branch and a CNN branch read the same input, then merge.

def parallel_cnn_lstm(n_lags, n_features, n_outputs):
    """P-CNN-LSTM: an LSTM branch and a CNN branch, concatenated, then Dense."""
    inputs = keras.Input(shape=(n_lags, n_features))

    lstm = layers.LSTM(LSTM_UNITS, activation="relu", kernel_initializer=init())(inputs)
    lstm = layers.Dense(DENSE_UNITS, activation="relu", kernel_initializer=init())(lstm)
    lstm = layers.Dropout(INNER_DROPOUT)(lstm)

    cnn = conv_block(inputs)
    cnn = layers.Dropout(INNER_DROPOUT)(cnn)

    x = layers.Concatenate()([lstm, cnn])
    x = layers.Dropout(FINAL_DROPOUT)(x)
    outputs = layers.Dense(n_outputs, kernel_initializer=init())(x)
    return compile_model(keras.Model(inputs, outputs, name="P-CNN-LSTM"))
  • The LSTM branch keeps only its final state (100), then Dense(100) and Dropout 0.2.
  • The CNN branch reads the raw 956 inputs directly and ends with 500 values after Flatten and Dropout 0.2.
  • Concatenate joins them into 600 values, then Dropout 0.3 and Dense(934).
  • Built with the Keras functional API because a Sequential model cannot branch. 1.84M parameters.
If asked

Why could parallel generalise better? Each branch learns different patterns and the output layer combines them, like a small ensemble.

lstm_baseline(n_lags, n_features, n_outputs)

The paper's LSTM benchmark from Table 3, used as our required simple baseline.

def lstm_baseline(n_lags, n_features, n_outputs):
    """Paper's LSTM benchmark: LSTM(100) -> Dense."""
    inputs = keras.Input(shape=(n_lags, n_features))
    x = layers.LSTM(LSTM_UNITS, activation="relu", kernel_initializer=init())(inputs)
    outputs = layers.Dense(n_outputs, kernel_initializer=init())(x)
    return compile_model(keras.Model(inputs, outputs, name="LSTM"))
  • LSTM(100) reads the 7 days and its final state goes straight to Dense(934). No CNN and no dropout. 517K parameters.

compile_model(model)

The paper's training setup from Algorithm 1.

def compile_model(model):
    """Adam, MSE loss, MAE metric (paper)."""
    model.compile(optimizer=keras.optimizers.Adam(LEARNING_RATE), loss="mse", metrics=["mae"])
    return model
  • Adam with learning rate 0.001 and MSE loss.
  • MAE is tracked as a metric because early stopping in train.py watches validation MAE.

run_name(...)

Builds a file name from the run's settings.

def run_name(model, seed, lags=7, log_sales=False, next_day_features=False):
    """e.g. 'p_cnn_lstm_s42' or 'p_cnn_lstm_lags14_s42'."""
    parts = [model]
    if lags != 7:
        parts.append(f"lags{lags}")
    if log_sales:
        parts.append("log")
    if next_day_features:
        parts.append("nextday")
    parts.append(f"s{seed}")
    return "_".join(parts)
  • Each setting that differs from the default adds a tag, e.g. p_cnn_lstm_nextday_s43.
  • The seed always comes last as _s<seed>. evaluate.py relies on this to group the 3 seeds of one model.

train(model, seed, dataset, ...)

One complete training run.

def train(model, seed, dataset="rossmann", lags=7, log_sales=False, next_day_features=False):
    keras.utils.set_random_seed(seed)          # fixes Python, NumPy and TF seeds
    tf.config.experimental.enable_op_determinism()

    sales, _, features, (train_end, val_end) = load(dataset)
    data, _ = make_windows(sales, features, lags, log_sales, next_day_features,
                           train_end, val_end)
    X_train, y_train, _ = data["train"]
    X_val, y_val, _ = data["val"]

    net = MODELS[model](X_train.shape[1], X_train.shape[2], y_train.shape[1])
    stop = keras.callbacks.EarlyStopping(monitor="val_mae", patience=PATIENCE,
                                         restore_best_weights=True)
    history = net.fit(X_train, y_train, validation_data=(X_val, y_val),
                      epochs=EPOCHS, batch_size=BATCH_SIZE, callbacks=[stop], verbose=2)

    name = run_name(model, seed, lags, log_sales, next_day_features)
    out = f"{OUT_DIR}/{dataset}"
    os.makedirs(f"{out}/models", exist_ok=True)
    os.makedirs(f"{out}/curves", exist_ok=True)
    net.save(f"{out}/models/{name}.keras")
    config = dict(model=model, seed=seed, dataset=dataset, lags=lags, log_sales=log_sales,
                  next_day_features=next_day_features)
    with open(f"{out}/models/{name}.json", "w") as f:
        json.dump(config, f)
    plot_curves(history.history, name, out)
    return name
  • Seeds: set_random_seed fixes Python, NumPy and TensorFlow at once; enable_op_determinism makes a re-run give identical numbers.
  • Data: only the train and validation splits are used. The test set is never touched here.
  • Build: sizes come from the data shapes, so the same code works for 934 Rossmann stores and 500 paper series.
  • Early stopping: watches val_mae with patience 10 and restores the weights from the best epoch.
  • Save: the model as .keras, its settings as .json (so evaluation rebuilds the same windows), and the learning curves.
If asked

Is shuffling the training windows a leak? No. Each window carries its own 7 days of history, so their order does not matter. Validation and test are still later in time.

plot_curves(history, name, out)

Saves the training and validation curves the rules ask for.

def plot_curves(history, name, out):
    """Training and validation loss (MSE) and MAE per epoch."""
    fig, axes = plt.subplots(1, 2, figsize=(10, 4))
    for ax, metric in zip(axes, ["loss", "mae"]):
        ax.plot(history[metric], label="train")
        ax.plot(history[f"val_{metric}"], label="validation")
        ax.set_title(f"{name} - {metric}")
        ax.set_xlabel("epoch")
        ax.legend()
    fig.tight_layout()
    fig.savefig(f"{out}/curves/{name}.png")
    plt.close(fig)
  • Two plots side by side: loss (MSE) and MAE, each with a train and a validation line, one point per epoch.

evaluate.py

Score every saved model

HORIZONS

The forecast horizons from the paper.

HORIZONS = (30, 90, 360)   # 360 only exists for the paper dataset's one-year test set
  • 360 days only fits the paper's one-year test set; it is skipped automatically for Rossmann's 92 test days.

metrics(actual, predicted, scored)

MAE, RMSE, MAPE and SMAPE over the store-days to score.

def metrics(actual, predicted, scored):
    """MAE, RMSE, MAPE and SMAPE over the store-days where `scored` is True."""
    a, p = actual[scored], predicted[scored]
    error = np.abs(a - p)
    return {
        "MAE": error.mean(),
        "RMSE": np.sqrt((error ** 2).mean()),
        "MAPE": 100 * (error / a).mean(),
        "SMAPE": 100 * (error / ((np.abs(a) + np.abs(p)) / 2)).mean(),
    }
  • actual[scored] keeps only open days, using a True/False mask the same shape as the predictions.
  • MAPE and SMAPE are the paper's equations (10) and (11). MAE and RMSE are required by the project rules.
If asked

Why skip closed days? Their sales are 0, and MAPE divides by the actual value.

score(name, dates, predicted, sales, is_open)

One result row per horizon.

def score(name, dates, predicted, sales, is_open):
    """One row per horizon: metrics over the first `h` days of `dates`."""
    actual = sales.loc[dates].values
    scored = (is_open.loc[dates].values == 1) & (actual > 0)   # Open Days only
    rows = []
    for h in HORIZONS:
        if h <= len(dates):
            rows.append({"run": name, "horizon": h,
                         **metrics(actual[:h], predicted[:h], scored[:h])})
    return rows
  • The scoring mask is (is_open == 1) & (actual > 0): the open days.
  • actual[:h] takes the first h days of the test period, which is how the 30, 90 and 360-day horizons are defined.

predict_model(config_path, sales, features, ends, split)

Loads one saved model and predicts in real sales units.

def predict_model(config_path, sales, features, ends, split):
    """Rebuild the model's windows, predict, and return real-unit sales."""
    with open(config_path) as f:
        cfg = json.load(f)
    data, scaler = make_windows(sales, features, cfg["lags"], cfg["log_sales"],
                                cfg["next_day_features"], *ends)
    X, _, dates = data[split]
    net = keras.models.load_model(config_path.replace(".json", ".keras"))
    predicted = to_sales(net.predict(X, verbose=0), scaler, cfg["log_sales"])
    return dates, predicted
  • Reads the run's JSON so a model trained with 14 lags or log sales gets the matching windows.
  • make_windows refits the scaler on the same training days, so it is identical to the one used in training.
  • to_sales converts the output back before scoring.

seasonal_naive(sales, dates)

The no-training baseline: each store sells what it sold 7 days earlier.

def seasonal_naive(sales, dates):
    """Each store sells what it sold 7 days earlier."""
    return sales.shift(7).loc[dates].values
  • shift(7) moves every row down a week. Every model must beat this floor.

main(dataset, split)

Scores every model, adds the naive baseline, and averages over seeds.

def main(dataset, split):
    sales, is_open, features, ends = load(dataset)
    out = f"{OUT_DIR}/{dataset}"
    rows = []
    dates = None
    for config_path in sorted(glob.glob(f"{out}/models/*.json")):
        dates, predicted = predict_model(config_path, sales, features, ends, split)
        name = os.path.basename(config_path).replace(".json", "")
        rows += score(name, dates, predicted, sales, is_open)
    rows += score("seasonal_naive_s0", dates, seasonal_naive(sales, dates), sales, is_open)

    per_run = pd.DataFrame(rows)
    per_run["model"] = per_run["run"].str.rsplit("_s", n=1).str[0]   # drop the seed
    summary = per_run.drop(columns="run").groupby(["horizon", "model"]).agg(["mean", "std"])

    per_run.to_csv(f"{out}/{split}_per_run.csv", index=False)
    summary.to_csv(f"{out}/{split}_summary.csv")
    pd.set_option("display.width", 200)
    pd.set_option("display.max_columns", 20)
    print(summary.round(2))
  • Loops over every saved .json, predicts and scores.
  • The naive baseline is named seasonal_naive_s0 so it goes through the same seed-stripping step.
  • rsplit("_s", n=1) splits on the last _s, so s_cnn_lstm_s42 becomes s_cnn_lstm.
  • Groups by horizon and model, takes the mean and std over seeds, and saves both CSV files.
  • --split val while choosing and --split test once at the end enforces the test-once rule.

forecast(store)

What the app shows for one store.

def forecast(store):
    actual = sales.loc[dates, store]
    scored = ((is_open.loc[dates, store] == 1) & (actual > 0)).values   # Open Days only

    fig, ax = plt.subplots(figsize=(11, 4))
    ax.plot(dates, actual, color="black", linewidth=2, label="actual")
    rows = []
    for label, pred in predictions.items():
        ax.plot(dates, pred[store], label=label)
        scores = metrics(actual.values, pred[store].values, scored)
        rows.append({"model": label, **{k: round(v, 2) for k, v in scores.items()}})

run_experiments.sh

Reproduce every result

The full experiment

Every training run and evaluation, in the order they were done. About 30 minutes on CPU.

#!/bin/sh
# Reproduces every result. Each training run takes about 1 minute on CPU.
set -e

# 1) Rossmann: the paper's models, the baseline and the three bonus candidates, 3 seeds each
for seed in 42 43 44; do
  for model in s_cnn_lstm p_cnn_lstm lstm; do
    python train.py --model $model --seed $seed
  done
  python train.py --model p_cnn_lstm --seed $seed --next-day-features   # candidate (a)
  python train.py --model p_cnn_lstm --seed $seed --lags 14             # candidate (b)
  python train.py --model p_cnn_lstm --seed $seed --log-sales           # candidate (c)
done
python evaluate.py --split val
# -> (a) wins on validation. Move the rejected candidates aside, then score the test set once:
mkdir -p results/rossmann/rejected_candidates
mv results/rossmann/models/p_cnn_lstm_lags14_* results/rossmann/models/p_cnn_lstm_log_* \
   results/rossmann/rejected_candidates/
python evaluate.py --split test

# 2) The paper's dataset: same models plus the chosen change, to compare with the paper itself
for seed in 42 43 44; do
  for model in s_cnn_lstm p_cnn_lstm lstm; do
    python train.py --model $model --seed $seed --dataset paper
  done
  python train.py --model p_cnn_lstm --seed $seed --dataset paper --next-day-features
done
python evaluate.py --split test --dataset paper
  • Rossmann: S-CNN-LSTM, P-CNN-LSTM, the LSTM baseline and the three bonus candidates, each with seeds 42, 43 and 44.
  • Choose on validation: candidate (a) wins, the other two are moved aside.
  • Test once: the test set is scored a single time.
  • Paper's dataset: the same models plus the chosen change, to compare with the paper's own numbers.
